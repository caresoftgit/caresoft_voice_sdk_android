1. Chuẩn bị

Cần JDK 17, Android SDK 35 và Gradle wrapper có trong repo. Chuẩn bị domain, API URL HTTPS, Voice App ID, backend cấp C2C token, package Android và Firebase project theo cấu hình backend. Chỉ dùng cấu hình do quản trị cấp cho ứng dụng của bạn.

Repo không chứa tài khoản hoặc môi trường mẫu đã đăng ký. Bản APK cài sẵn mở ở màn hình đăng nhập trống, không tự tạo cuộc gọi. App ID và API URL phải nhập trước khi đăng nhập.

2. Cài SDK vào ứng dụng

Chạy ở root repo:

python3 scripts/setup-sdk.py
./gradlew :demo:assembleDebug :consumer-java:assembleDebug

Mở root repo bằng Android Studio và chạy module demo. Nếu dùng CLI, đặt ANDROID_HOME hoặc tạo local.properties với sdk.dir của máy. Dependency cần Google Maven/Maven Central ở lần resolve đầu.

Để tích hợp vào app riêng, chép thư mục packages/maven đã giải nén tới vendor/caresoft/maven trong app. Trong settings.gradle của app:

dependencyResolutionManagement {
    repositories {
        maven { url uri('vendor/caresoft/maven') }
        google()
        mavenCentral()
    }
}

Trong module app:

dependencies {
    implementation 'vn.caresoft:voice-android:1.0.2'
    implementation 'vn.caresoft:voice-android-ui:1.0.2' // tùy chọn
}

Giữ toàn bộ Maven repository cùng AAR/POM/Gradle metadata để Gradle lấy đủ dependency. Không dùng flatDir chỉ chép riêng AAR. Đặt minSdk của app từ 26 trở lên; dùng demo làm cấu hình build tham khảo.

Nâng từ 1.0.1 lên 1.0.2

Tải bộ tích hợp 1.0.2, kiểm tra checksum rồi chạy lại python3 scripts/setup-sdk.py. Cập nhật cả hai dependency core/UI về 1.0.2; khi chép sang app riêng, thay bộ Maven repository cũ bằng bộ mới cùng metadata. Không cần đổi public API hoặc thêm cấu hình chọn chế độ hoạt động.

Giữ applicationId, cấu hình Firebase, domain/App ID và provider của ứng dụng. Demo/APK bàn giao không chứa cấu hình thử nghiệm riêng. Sau nâng cấp, chạy checklist tích hợp, đặc biệt nghe hai chiều, chuyển thiết bị âm thanh, DTMF và nhận cuộc gọi từ nền.

3. Quyền và thành phần Android

SDK merge ConnectionService, receiver và foreground service vào manifest host. Kiểm tra merged manifest và bảo đảm host có quyền phù hợp:

Quyền Cách dùng
RECORD_AUDIO Xin runtime ở foreground trước nghe/gọi
POST_NOTIFICATIONS Xin runtime trên Android 13+
BLUETOOTH_CONNECT Xin runtime trên Android 12+ nếu dùng Bluetooth
MANAGE_OWN_CALLS Self-managed Telecom; không yêu cầu app làm dialer mặc định
FOREGROUND_SERVICE, FOREGROUND_SERVICE_PHONE_CALL, FOREGROUND_SERVICE_MICROPHONE Dịch vụ nghe/gọi theo Android target SDK
USE_FULL_SCREEN_INTENT Kiểm tra khả năng được cấp trên Android 14+, cung cấp notification fallback

Không cần READ_PHONE_NUMBERS chỉ để dùng cuộc gọi VoIP. Không bỏ kiểm tra microphone hoặc dùng FCM để mở micro trái giới hạn OS. Xem manifest demo và khả năng tương thích.

4. Khởi tạo client và phiên

Các lớp SDK dùng package vn.caresoft.voice; UI dùng vn.caresoft.voice.ui.VoiceCallView.

Giữ một CaresoftVoiceClient ở Application/service lâu hơn vòng đời Activity. Tạo client/createCall trên main thread, gọi suspend API từ coroutine có scope phù hợp. installationId phải ổn định trên một cài đặt và không dùng mã thiết bị nhạy cảm.

val options = VoiceOptions(
    domain = domain,
    appId = appId,
    apiBaseUrl = apiUrl,
    installationId = installationId,
    tokenProvider = TokenProvider { authenticatedBackend.fetchC2CToken() },
    appVersionCode = appVersionCode,
    pushConfig = AppPushConfig(context.packageName, "default")
)
val client = CaresoftVoiceClient(context.applicationContext, options)
CaresoftVoicePush.configure(client)

Các biến trên thuộc cấu hình/backend của app, không phải hằng số credential trong SDK. fetchC2CToken() minh họa API của backend khách hàng; endpoint và cơ chế xác thực do app triển khai. Xem ví dụ Kotlin đã compile.

  • connect() đăng nhập bằng C2C từ TokenProvider.
  • checkSession() kiểm tra/khôi phục phiên đã lưu; không đăng nhập lại ngầm khi mạng lỗi.
  • AUTHENTICATED: có phiên được xác minh; UNAUTHENTICATED: cần đăng nhập; UNKNOWN: chưa xác minh được, giữ credential và thử lại khi có mạng.
  • Không chuyển UI thành đăng nhập thành công trước khi API hoàn tất. Không coi lỗi mạng là sai mật khẩu.

Demo xóa token nhập tay sau connect; khi phiên hết hạn cần nhập lại. Provider production phải tự lấy token mới từ backend đã xác thực.

5. Nhân viên và đầu số gọi ra

Đọc getAvailability() và getCallDevice(). Chọn Mobile bằng selectCallDevice(CallDevice.MOBILE), bật sẵn sàng bằng setAvailability(Availability.AVAILABLE) theo thao tác người dùng. Đăng nhập không tự đổi hai lựa chọn này. Không đổi thiết bị trong lúc có cuộc gọi.

getCallingLines() trả các CallingLine(id, label, isDefault). Hiển thị label, truyền id được chọn vào CallOptions.callerId; không dùng số hiển thị làm id. Khi tải thất bại, báo lỗi và cho thử lại, không giả thành danh sách rỗng thành công.

6. Gọi đi

Sau khi đã có phiên và quyền microphone, chạy từ coroutine trên main thread:

val call = client.createCall(CallOptions(to = phoneNumber, callerId = selectedLineId))
call.start()

createCall() giữ chỗ cuộc gọi đồng bộ; chỉ một call hoạt động. Không tạo/start lại khi Activity xoay màn hình. Giữ call ở tầng Application/service, dùng getActiveCall() để gắn lại UI.

Trạng thái công khai: NEW → DIALING/RINGING/CONNECTING → ACTIVE → ENDED. Theo dõi cả state và mediaState; phải thử tiếng hai chiều để xác nhận cuộc gọi có âm thanh. Không coi kết nối client là cuộc gọi đã được nhận.

7. Nhận cuộc gọi bằng FCM

Host sở hữu FirebaseMessagingService. Đăng ký Android client đúng package và cấu hình server cùng project theo hướng dẫn FCM. Nếu app đã có messaging service, forward message từ service đó; không khai báo thêm service thứ hai cho cùng sự kiện. Với app chưa có service, khai báo service của bạn trong <application>:

<service
    android:name=".VoiceMessagingService"
    android:exported="false">
    <intent-filter>
        <action android:name="com.google.firebase.MESSAGING_EVENT" />
    </intent-filter>
</service>

VoiceMessagingService là lớp do host triển khai, kế thừa FirebaseMessagingService. Xem service demo và đăng ký token trong demo.

Sau đăng nhập, lấy FCM token và đăng ký:

client.registerPushToken(
    PushRegistration(fcmToken, installationId, context.packageName, "default")
)

Xử lý token rotation cả khi Activity chưa mở. Demo lưu cờ retry theo tài khoản và dùng JobScheduler kiểm tra phiên, lấy FCM token mới nhất rồi đăng ký lại; không lưu FCM token plaintext. Logout/đổi client phải làm mất hiệu lực công việc cũ.

Ở Application.onCreate(), khôi phục cấu hình app và tạo/configure client trước khi forward message:

// Chạy trong cửa sổ xử lý FCM và coroutine theo lifecycle của host.
CaresoftVoicePush.receive(message.data)

SDK không tạo FirebaseMessagingService thứ hai. Không log data payload. Quan sát ClientEvent.IncomingCall và ClientEvent.CallRestored, giữ VoiceCall rồi hiển thị UI. Khi Activity mở lại từ thông báo, gọi getActiveCall() để lấy cuộc gọi hiện tại. UI riêng gọi call.answer() để nhận, call.reject() để từ chối; quyền micro cần cấp ở foreground trước khi nhận.

Trên Android 14+, app ở nền có thể bị chặn quyền microphone/foreground service; cung cấp notification mở app. High-priority data push không bảo đảm quyền chạy mọi tác vụ nền. Force-stop vẫn cần người dùng mở lại app. Xem demo đầy đủ thay vì chỉ chép vài dòng nhận message.

8. UI cuộc gọi

Thêm dependency voice-android-ui:1.0.2 nếu dùng màn hình sẵn có. VoiceCallView là Android View; đặt trong Activity/Fragment hoặc AndroidView của Compose. Host chịu trách nhiệm điều hướng, quyền runtime và giữ VoiceCall lâu hơn vòng đời màn hình.

// Trong Activity/Fragment, sau khi host đã xử lý quyền micro.
val callView = VoiceCallView(requireContext())
container.addView(callView, ViewGroup.LayoutParams(
    ViewGroup.LayoutParams.MATCH_PARENT, ViewGroup.LayoutParams.MATCH_PARENT))
callView.lineLabel = selectedLine?.label // tùy chọn; chỉ là nhãn hiển thị
callView.bind(call)

// Trong Fragment.onDestroyView() hoặc lúc bỏ view khỏi màn hình:
callView.unbind()

container, selectedLine và call là biến của app. Trong Activity dùng this thay requireContext(). lineLabel không thay đổi đầu số thực: truyền selectedLine.id vào CallOptions.callerId khi tạo cuộc gọi. Đặt lại nhãn khi bind một call khác hoặc đặt null để ẩn.

Trạng thái UI SDK hiển thị / xử lý
Incoming đang đổ chuông Người gọi, Trả lời, Từ chối
Outgoing mới tạo Nút Gọi; host có thể gọi start() trước khi hiển thị
Đang kết nối Trạng thái và nút kết thúc
ACTIVE Thời lượng, mute/unmute, hold/unhold, thiết bị âm thanh và bàn phím DTMF
ENDED Thông tin cuộc gọi, thời lượng và lý do kết thúc; không còn nút điều khiển

bind() chỉ gắn UI; không tự gọi/nhận cuộc gọi. unbind() hủy quan sát UI; không hangup hoặc dispose. UI không xin quyền micro thay app. Xin quyền trước khi người dùng bấm Gọi/Trả lời; không tự nhận lại sau lỗi khi chưa kiểm tra trạng thái call.

Giữ client và call ở Application/service của host. Khi xoay màn hình hoặc trở lại từ thông báo, lấy client.getActiveCall() và bind lại; không tạo/start một call mới. getActiveCall() không giữ cuộc gọi đã kết thúc: nếu muốn tiếp tục hiện chi tiết ENDED, host giữ tham chiếu call hoặc snapshot đến khi người dùng đóng. Thêm nút Đóng/Quay lại ở màn hình host, sau đó unbind và bỏ tham chiếu khi phù hợp. Cuộc gọi tiếp theo dùng object mới.

Java dùng cùng UI:

VoiceCallView callView = new VoiceCallView(this);
callView.setLineLabel(selectedLine.getLabel());
callView.bind(call);
// Trong onDestroy() hoặc trước khi bỏ view:
callView.unbind();

Tự dựng UI: dùng call.snapshots hoặc call.observe, đọc call.getSnapshot() ngay khi gắn màn hình và hủy VoiceSubscription khi view bị hủy. Hiển thị lỗi từ CallEvent.Error, cập nhật route từ CallEvent.AudioRoutesChanged; không hangup/dispose chỉ vì đổi màn hình. Không phát thêm chuông trong UI: thông báo cuộc gọi đến đã dùng chuông/rung hệ thống theo cài đặt người dùng.

Demo có UI của SDK / UI tự dựng dùng chung một VoiceCall. Xem demo và ví dụ Java.

9. Điều khiển cuộc gọi

  • setMuted(true/false), setHeld(true/false): state thay đổi sau xác nhận server; lỗi cần hiển thị, không tự giả thành công.
  • sendDTMF("123#"): dùng khi ACTIVE; không gửi chuỗi ngoài 0–9/A–D/*/#. Chờ thao tác hoàn tất trước chuỗi tiếp theo; nếu yêu cầu thất bại/hủy, hiển thị lỗi và cho phép thử lại khi cuộc gọi còn ACTIVE.
  • getAudioRoutes(): danh sách route hệ thống hỗ trợ, với id/name/selected. setAudioRoute(id) gửi yêu cầu; cập nhật lựa chọn từ CallEvent.AudioRoutesChanged.
  • Không hardcode AudioRoute id, không xin thêm AudioManager focus hoặc gọi setCommunicationDevice để tranh quyền với SDK của cùng cuộc gọi.
  • getStats(): số liệu media có thể null khi chưa có mẫu. Byte count tăng không tự chứng minh người đối ứng nghe được âm thanh.
  • hangup() trả EndResult(localEnded, serverAcknowledged). Kết thúc cục bộ có thể thành công dù server chưa xác nhận.

SDK quản lý âm thanh của cuộc gọi. Khi có cuộc gọi khác hoặc mất quyền âm thanh, kiểm tra trạng thái và tiếng thực tế trước khi tiếp tục; unhold là thao tác riêng của người dùng.

10. Java, lỗi và vòng đời

Java dùng TokenProviders.fromCallback(CallbackTokenProvider) và overload VoiceCallback<T>. Backend cấp token bất đồng bộ; không block main thread. Ví dụ khởi tạo trên main thread:

// backendTokenProvider: CallbackTokenProvider do app triển khai,
// gọi backend đã xác thực rồi hoàn tất onSuccess(token) / onError(error).
VoiceOptions options = new VoiceOptions(
    domain, appId, apiUrl, installationId,
    TokenProviders.fromCallback(backendTokenProvider),
    java.util.Collections.emptyList(), appVersionCode,
    new AppPushConfig(getPackageName(), "default")
);
CaresoftVoiceClient client = new CaresoftVoiceClient(getApplicationContext(), options);
CaresoftVoicePush.configure(client);
client.connect(new VoiceCallback<kotlin.Unit>() {
    @Override public void onSuccess(kotlin.Unit value) {
        // Cập nhật màn hình đã đăng nhập; tải trạng thái nhân viên/đầu số.
    }
    @Override public void onError(VoiceError error) {
        // Hiển thị lỗi; chỉ log error.getCode() và error.getOperation().
    }
});

Các biến cấu hình và provider trên do app cung cấp. Với gọi đi, tạo VoiceCall call = client.createCall(new CallOptions(number)); trên main thread, giữ call rồi gọi call.start(callback). Không tạo call lại từ callback UI khi xoay màn hình. Java nhận FCM qua client.receivePush(data, callback) sau khi đã tạo client. Xem mẫu Java đầy đủ cho điều khiển, route, stats, push và logout.

VoiceError có code, operation, retryable, callId. Hiển thị lỗi và chỉ retry khi phù hợp với trạng thái hiện tại. Log mã lỗi, phiên bản và timestamp; không log token hoặc phản hồi mạng.

Khi đổi domain/nhân viên, kết thúc cuộc gọi hiện tại rồi gọi logout(), CaresoftVoicePush.clear(oldClient) và dispose() client cũ; hủy subscription/job đăng ký push của tài khoản cũ trước khi tạo client mới. Không dispose khi chỉ đóng Activity.

logout() trả LogoutResult với xác nhận riêng app session/voice session và việc xóa credential cục bộ. Không coi local clear là server đã thu hồi phiên. Xem API và xử lý lỗi.

11. Nghiệm thu trước phát hành

Chạy checklist trên thiết bị/OS của sản phẩm, gồm gọi ra, nhận từ nền/khóa/cold-start, hai chiều, route, token rotation, logout, mạng yếu và giới hạn OEM. Kết quả trên một máy hoặc APK build thành công không thay thế nghiệm thu các ca đó.

API Kotlin / Java — 1.0.2

Public package: vn.caresoft.voice; UI tùy chọn: vn.caresoft.voice.ui.VoiceCallView. API mạng/điều khiển dùng Kotlin suspend và overload callback Java. Ví dụ đã compile nằm trong consumer Java và recipe Kotlin.

Client

API Kết quả/ý nghĩa
CaresoftVoiceClient(context, options) Client giữ phiên và cuộc gọi; dùng applicationContext
connect() Đăng nhập bằng C2C TokenProvider
checkSession(): SessionInfo Xác minh phiên đã lưu; AUTHENTICATED/UNAUTHENTICATED/UNKNOWN
getSnapshot(): ClientSnapshot Session, connection, availability, device, readiness, activeCall
snapshots / observe(handler) StateFlow hoặc ClientEvent + EventMeta; observe trả VoiceSubscription
getAvailability() / setAvailability(value) Đọc/đổi ca trực, server xác nhận
getCallDevice() / selectCallDevice(value) Mobile/Browser/Other/Unknown; không đổi trong call

checkReadiness(): Readiness auth, microphone, callUI, push, device: READY/BLOCKED/UNKNOWN

receivePush(data): VoiceCall? Forward FCM data khi đã khởi tạo client
createCall(CallOptions): VoiceCall Đồng bộ trên main, reserve một cuộc gọi
getActiveCall(): VoiceCall? Gắn lại UI vào cuộc gọi hiện tại
logout(): LogoutResult Xác nhận app/voice session và local clear riêng

Cấu hình thường dùng

VoiceOptions Cách cung cấp
domain, appId, apiBaseUrl Cấu hình được Caresoft cấp cho ứng dụng
installationId ID ổn định của một lần cài đặt
tokenProvider Provider lấy C2C token từ backend đã xác thực
appVersionCode Version code của app, dạng String
pushConfig AppPushConfig(applicationId, "default") cho FCM
operationTimeoutMs Timeout thao tác, mặc định 15000 ms
appName Tên hiển thị, mặc định "Caresoft Voice"

Năm tham số đầu bắt buộc. Các tùy chọn còn lại dùng mặc định trừ khi được hướng dẫn riêng. Không dùng provider chứa token cố định trong app phát hành.

TokenProvider.getToken(): String là suspend; Java dùng CallbackTokenProvider + TokenProviders.fromCallback. Provider trả C2C token. AppPushConfig(applicationId, environment="default") và PushRegistration(token, installationId, applicationId, environment="default") phải cùng scope.

VoiceCall

API Kết quả/ý nghĩa
start() Gọi đi sau createCall
answer() / reject() Nhận/từ chối incoming
hangup(): EndResult Kết thúc local + serverAcknowledged
setMuted(Boolean) / setHeld(Boolean) Chỉ dùng khi ACTIVE, state theo ACK server
sendDTMF(String) 0–9/A–D/*/#
getAudioRoutes(): List id/name/selected do hệ thống cung cấp
setAudioRoute(id) Yêu cầu route; chờ AudioRoutesChanged cho lựa chọn thực
getStats(): CallStats timestamp, packetsLost, jitterSeconds, roundTripTimeSeconds, bytesSent/Received
getSnapshot(): CallSnapshot State và mediaState độc lập; giữ snapshot terminal
snapshots / observe(handler) StateFlow hoặc CallEvent; hủy subscription khi view hủy

CallOptions(to, callerId=null, ticketId=null). CallSnapshot có id, direction, remote, state, mediaState, muted, held, serverCallId, endReason, createdAt, connectedAt, endedAt. Các mốc thời gian trong CallSnapshot là Unix milliseconds; không dùng ordinal enum làm protocol value.

CallState: NEW, DIALING, RINGING, CONNECTING, ACTIVE, ENDED. MediaState: NOT_STARTED, CONNECTING, CONNECTED, DISCONNECTED, FAILED. ENDED terminal; không tái sử dụng call đã kết thúc.

EndReason: LOCAL_ENDED, REMOTE_ENDED, REJECTED, MISSED, ANSWERED_ELSEWHERE, CANCELED_ELSEWHERE, AUTH_FAILED, CONNECTION_FAILED, BUSY, DISPOSED. Dùng để hiển thị kết quả; không suy diễn nguyên nhân chi tiết chỉ từ BUSY hoặc CONNECTION_FAILED. Với ANSWERED_ELSEWHERE/CANCELED_ELSEWHERE, đóng UI nhận cuộc gọi và hiển thị kết quả phù hợp; không gọi reject/end thêm từ callback kết thúc.

Events và UI

ClientEvent: SessionChanged, ConnectionChanged, AvailabilityChanged, CallDeviceChanged, IncomingCall, CallRestored, Error.

CallEvent: Changed(snapshot), AudioRoutesChanged(routes), Error(error). EventMeta gồm clientId/callId/sequence/timestamp; bỏ event của client cũ sau khi đổi tài khoản.

VoiceCallView(context) hoặc khai báo bằng XML; dùng trên main thread:

API UI Hành vi
bind(call) Gắn và hiển thị snapshot hiện tại, cập nhật theo call; không tự gọi/nhận
unbind() Hủy quan sát UI; không kết thúc/dispose call
lineLabel: String? Nhãn đầu số tùy chọn; không thay callerId; Java dùng setLineLabel()

UI hiển thị incoming nhận/từ chối, outgoing, trạng thái kết nối, thời lượng, điều khiển ACTIVE, bàn phím DTMF và kết quả ENDED. Host xin quyền runtime trước thao tác nghe/gọi, cung cấp điều hướng Đóng/Quay lại, giữ client/call qua Activity recreation và unbind khi hủy view. Nếu cần giữ màn hình ENDED sau đó, host giữ call/snapshot vì getActiveCall() chỉ trả call đang hoạt động. Xem tích hợp UI. Không giữ Activity trong client/service.

Java callback có onSuccess(T) và onError(VoiceError). Các API điều khiển không có kết quả dữ liệu trả kotlin.Unit; reject/hangup trả EndResult, logout trả LogoutResult. Mẫu compile là nguồn tham khảo chữ ký khi tích hợp Java.

VoiceError(code, operation, retryable, callId) có message an toàn theo mã lỗi. Không diễn giải serverAcknowledged=false là cuộc gọi vẫn còn local; kiểm tra hai trường EndResult riêng.

Push bridge và lỗi

CaresoftVoicePush.configure(client) đặt client nhận data message; gọi tại Application sau khởi tạo. Kotlin dùng CaresoftVoicePush.receive(data); Java dùng client.receivePush(data, callback). CaresoftVoicePush.clear(client) gỡ đúng client cũ khi đăng xuất/đổi tài khoản. Host cung cấp FirebaseMessagingService, cấu hình Firebase và cơ chế retry đăng ký token.

Mọi API bất đồng bộ có thể lỗi. Trong coroutine bắt VoiceError; không nuốt cancellation của coroutine host. Java xử lý onError. Xem xử lý lỗi để biết các bước kiểm tra và thông tin được phép gửi hỗ trợ.

Liên hệ quản trị Caresoft để đăng ký ứng dụng thoại cho domain, package Android và cấu hình push. Không sử dụng cấu hình của ứng dụng khác. Các ví dụ trong tài liệu dùng biến cấu hình, không cung cấp môi trường đăng nhập sẵn.

C2C token từ backend

  1. App đăng nhập backend của bạn bằng cơ chế xác thực hiện có.
  2. Backend kiểm tra nhân viên và quyền sử dụng thoại, cấp C2C token theo hợp đồng Voice API do Caresoft cung cấp.
  3. App nhận token qua HTTPS; TokenProvider trả token đó cho SDK.
  4. Khi cần token mới, provider tiếp tục gọi backend đã xác thực. Báo lỗi khi phiên app hết hạn thay vì trả token cũ hoặc chuỗi rỗng.

Endpoint, định dạng yêu cầu và header xác thực thuộc backend của bạn; SDK không quy định một endpoint cấp token chung. Không đặt Voice API signing secret trong source, BuildConfig, resource hoặc cấu hình mà client đọc được. Provider trả C2C token, không trả khóa ký, FCM token hoặc token phiên SDK.

Demo có chế độ thử endpoint HTTPS trả:

{ "token": "C2C_TOKEN_FROM_YOUR_BACKEND" }

Endpoint demo không tự gắn header xác thực của backend khách hàng. Production triển khai TokenProvider bằng HTTP client đã xác thực của app. Demo từ chối redirect, URL chứa user/password và phản hồi quá 64 KiB. Chế độ Agent ID + Voice API token chỉ dùng thử có kiểm soát.

Firebase và cuộc gọi đến

  1. Tạo/chọn Firebase project của bạn; đăng ký Android applicationId chính xác.
  2. Với demo, đặt google-services.json Android client cục bộ tại demo/google-services.json rồi build lại. Với app riêng, cấu hình Firebase theo cách của app và khởi tạo Firebase trước khi lấy FCM token.
  3. Đăng ký thông tin project, package và cấu hình gửi FCM với backend/Caresoft. Firebase service-account/private key chỉ đưa vào hệ thống server, không vào app hoặc repo demo.
  4. Tạo client với AppPushConfig(applicationId, "default"). Sau khi xác minh phiên, lấy FCM token và gọi registerPushToken(PushRegistration(...)) với cùng installationId/package/environment.
  5. Xử lý FirebaseMessagingService.onNewToken() kể cả khi chưa có Activity. Lưu yêu cầu retry nếu chưa đăng nhập hoặc mất mạng; vô hiệu yêu cầu cũ khi đổi tài khoản. Xem PendingPushRegistration và DemoTokenJobService trong demo.
  6. Trong Application, tạo client và gọi CaresoftVoicePush.configure(client) trước khi forward data message tới CaresoftVoicePush.receive().

Backend cần gửi high-priority data message theo hợp đồng cuộc gọi Caresoft. Không tự chế payload; không log payload nhận được. FCM có cửa sổ xử lý ngắn và chịu giới hạn nền Android. SDK không tự đăng ký một FirebaseMessagingService thay host.

Firebase khởi tạo thành công chưa chứng minh backend gửi đúng cuộc gọi. Kiểm tra đăng ký token phía backend và nhận cuộc gọi trên thiết bị thật. Chưa cấu hình Firebase vẫn có thể thử gọi đi sau khi đăng nhập, nhưng chưa thể nghiệm thu cuộc gọi đến qua push.

Mạng và thông báo

Cho phép kết nối tới các địa chỉ/cổng được Caresoft cấp cho môi trường của bạn. Không tắt kiểm tra HTTPS/TLS. Nếu tổ chức có VPN, proxy hoặc firewall, phối hợp quản trị mạng và thử cả Wi-Fi/mobile data.

Thông báo cuộc gọi đến dùng chuông/rung theo cài đặt Android. Host xin quyền thông báo và hướng dẫn người dùng bật kênh Cuộc gọi đến; không phát thêm chuông chồng lên thông báo. Full-screen khi khóa máy phụ thuộc quyền hệ thống, còn thao tác nhận cần quyền micro đã cấp ở foreground. Xem yêu cầu Android.

Bảo vệ cấu hình và credential

  • Lấy C2C token từ backend đã xác thực và kiểm tra quyền đúng nhân viên. Không đóng gói khóa ký Voice API, Firebase service-account/private key hoặc token đăng nhập vào APK.
  • Không log số điện thoại, C2C/FCM token, raw push payload hoặc phản hồi mạng chứa credential. Dùng VoiceError.code/operation, phiên bản và timestamp khi hỗ trợ.
  • SDK mặc định bảo vệ phiên đã lưu bằng Android Keystore. Host bảo vệ phiên backend riêng và tránh đưa token vào Activity saved state, backup, clipboard hoặc crash breadcrumb.
  • Demo chỉ giữ token nhập tay trong RAM, xóa khỏi provider sau đăng nhập, chặn screenshot màn hình token và tắt backup dữ liệu app. Khi phiên hết hạn cần nhập token mới.
  • Không coi SharedPreferences là nơi lưu bí mật. Chỉ lưu cấu hình cần để khôi phục app, bảo vệ dữ liệu nhạy cảm bằng cơ chế phù hợp.
  • Đổi domain/nhân viên: kết thúc cuộc gọi, logout, clear push bridge và dispose client cũ. Kiểm tra LogoutResult: xóa credential cục bộ không thay thế xác nhận thu hồi phiên phía server.
  • Không tắt TLS validation, đưa credential vào query string hoặc chuyển tiếp token qua redirect sang host khác.
  • APK demo dùng debug signing để thử. App phát hành cần applicationId, Firebase và signing riêng của khách hàng.
